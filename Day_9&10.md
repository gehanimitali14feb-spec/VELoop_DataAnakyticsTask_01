## 1. Double-Entry Wallet Transaction Model (D1)
To ensure auditability and prevent balance drift, all currency changes must post to an immutable append-only ledger:

$$\text{Available Liquid Balance} = \sum(\text{Credits}) - \sum(\text{Holds}) - \sum(\text{Debits}) + \sum(\text{Reversals})$$

| Field Name | Type | Required? | Description | Example / Rule |
| :--- | :--- | :--- | :--- | :--- |
| `transaction_id` | String | Yes | Unique financial ledger identifier | `TXN_20260901_0001` |
| `user_id` | String | Yes | Owner of the wallet account | `VLUSR000001` |
| `timestamp` | ISO-8601 UTC | Yes | UTC timestamp of ledger entry | `2026-09-01T12:00:00Z` |
| `transaction_type` | Enum | Yes | Classification of movement | `EARN_CREDIT`, `BONUS_CREDIT`, `WITHDRAWAL_HOLD`, `WITHDRAWAL_SETTLE`, `REVERSAL` |
| `amount` | Decimal(12,4)| Yes | Magnitude of change | Strict positive numeric value (> 0) |
| `currency_unit` | Enum | Yes | Segmented currency | `VES`, `Tokens`, `Gems`, `Spins` |
| `reference_id` | String | Yes | Link to originating task or withdrawal | `ACT0000001` or `WTH0000123` |
| `balance_after` | Decimal(12,4)| Yes | Snapshot balance post-transaction | Verifiable running total |

## 2. Withdrawal Lifecycle State Machine (D2)
Withdrawal requests follow four distinct operational states:

$$\text{WITHDRAWAL\_REQUESTED} \longrightarrow \text{UNDER\_REVIEW} \longrightarrow \text{PROCESSING\_GATEWAY} \longrightarrow \text{COMPLETED}$$
*(Terminal error states: `REJECTED`, `REVERSED_REFUNDED`)*

1. **Requested:** User initiates withdrawal; amount is debited from available balance and credited to `Escrow_Hold`.
2. **Under Review:** Anti-fraud heuristics evaluate velocity, IP clustering, and task completion legitimacy.
3. **Processing Gateway:** Payout batch dispatched to banking or payment provider.
4. **Completed:** Gateway returns settlement success; `Escrow_Hold` is cleared.

## 3. Withdrawal KPI Definitions (D3)

| KPI Name | Formula | Purpose | Frequency | Stakeholder |
| :--- | :--- | :--- | :--- | :--- |
| **Withdrawal Completion Rate** | $\frac{\text{Completed Withdrawals}}{\text{Total Requested Withdrawals}} \times 100$ | Measure operational payout success rate | Daily | Operations / Finance |
| **Payout Turnaround Time (TAT)** | $\text{Timestamp}_{\text{completed}} - \text{Timestamp}_{\text{requested}}$ | Track fulfillment speed and user satisfaction | Weekly | Operations |
| **Rejection Ratio** | $\frac{\text{Rejected Withdrawals}}{\text{Total Requested Withdrawals}} \times 100$ | Monitor fraud detection rate and rule friction | Daily | Risk & Compliance |
| **Pending Escrow Queue Volume** | $\sum(\text{Amount of Withdrawals with status 'Under Review' or 'Processing'})$ | Track outstanding financial liabilities | Hourly | Finance / Treasury |
